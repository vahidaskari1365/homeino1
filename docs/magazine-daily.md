# مجله و ترندهای روز هومینو — راهنمای گردش کار (نسخه چنددسته‌ای)

هومینو باید «مرجع فارسی دیزاین خانه» باشد. این سند توضیح می‌دهد سیستم ترندها چطور
هر روز، خودکار و ۳ نوبت، محتوای تازه و **اورجینال** در همه دسته‌ها تولید می‌کند.

## معماری

```
فیدهای RSS منابع معتبر (AD، Livingetc، Homes & Gardens، Ideal Home، Dwell،
Design Milk، Wallpaper، Surface) + ۱۰ فید صنفی Google News برای دسته‌های
محصول (فرش، روشنایی، تابلو، گلدان و گیاه، پرده، کف‌پوش، کمد، دیوارپوش، …)
        │  روزی ۳ نوبت (GitHub Actions cron) — هر نوبت دوباره سرچ می‌کند
        ▼
scripts/magazine-daily.mjs  (+ پیکربندی مشترک scripts/lib/homeino-categories.mjs)
  ۱. سرچ: فقط مطالب تازه (ضدتکرار URL/عنوان با آرشیو) — اگر تازه نبود،
     بدون کامیت خارج می‌شود («فقط اگر مطلب جدید بود پست کن»)
  ۲. دسته‌یابی خودکار با CATEGORY_KEYWORDS (۲۱ دسته) + انتخاب متنوع‌بین‌دسته
     (پاس ۱: حداکثر ۱ بریف از هر دسته — پاس ۲: تکمیل سهمیه؛ هدف ۱۲ بریف/روز)
  ۳. استخراج متن منبع + کاور: og:image خود منبع → عکس هم‌موضوع → استخر لوکال
  ۴. بریف فارسی با LLM: جمله اول خودبسنده سئو/GEO + فیلدهای keywords و faq
     (پرسش‌وپاسخ برای FAQPage JSON-LD و استناد دستیارهای هوشمند)
  ۵. مقاله کامل روزانه مجله (articles.json) از بریف منتخب
  ۶. ادغام در src/content/trends/trends.json (نگه‌داری ۱۲۰ روز)
        ▼
سایت — همان فایل JSON استاتیک خوانده می‌شود:
  /trends                    مرجع اصلی + چیپ‌های دسته‌ای
  /trends/category/{slug}    هاب ترندِ هر دسته (کلستر سئو، FAQPage JSON-LD)
  /trends/[date]             بریف‌های هر روز (+ FAQPage JSON-LD)
  /category/{productSlug}    صفحه خرید — به هاب ترند لینک می‌دهد (و برعکس)
  /feed.xml                  RSS کل سایت (ترندها + مجله)
  sitemap                    هاب‌ها و بریف‌ها خودکار اضافه می‌شوند
```

## دسته‌ها — منبع حقیقت دوگانه (عمداً هم‌راستا)

- **سمت تولید:** `scripts/lib/homeino-categories.mjs` — ۱۰ دسته محصول سایت
  (مبل و مبلمان، فرش و قالیچه، کف‌پوش، روشنایی و لوستر، تابلو و دیوارکوب،
  گلدان و گیاه، پرده و منسوجات، دکوری و اکسسوری، کمد و ذخیره‌سازی، دیوارپوش)
  + موضوع‌های عمومی دیزاین.
- **سمت نمایش:** `TREND_CATEGORY_META` در `src/lib/trends.ts` — همین ۲۱ برچسب،
  با اسلاگ لاتین هاب و `productSlug` برای لینک متقابل «محتوا ↔ خرید».
  تغییر برچسب باید هم‌زمان در هر دو انجام شود (تست trends.test.ts حافظ این قرارداد است).

## قواعد محتوا (ضدکپی)

- بریف‌ها **بازنویسی اختصاصی** هستند؛ ترجمه‌ی تحت‌اللفظی و کپی ممنوع است.
  پرامپت سیستم صراحتاً ترجمه‌ی مستقیم را منع می‌کند و فقط «واقعیت‌ها + ایده‌ها» را مجاز می‌داند.
- نام و لینک منبع اصلی همیشه کنار هر بریف نمایش داده می‌شود (`source` و `extraSources`).
- هر بریف یک بخش «برای خانه ایرانی» دارد که ارزش افزوده‌ی محلی است.
- تست‌های `src/lib/trends.test.ts` شکل داده را قفل می‌کنند (خلاصه‌ی کوتاه = شکست تست).

## راه‌اندازی در گیت‌هاب

۱. در Settings → Secrets and variables → Actions این سه Secret را بسازید
   (هر سرویس سازگار با `chat/completions`OpenAI کار می‌کند):
   - `LLM_API_KEY` — کلید سرویس
   - `LLM_BASE_URL` — مثل `https://api.openai.com/v1`
   - `LLM_MODEL` — اختیاری (پیش‌فرض `gpt-4o-mini`)

۲. ورک‌فلو `.github/workflows/magazine-daily.yml` روزی ۳ نوبت اجرا می‌شود؛
   هر نوبت دوباره سرچ می‌کند و اگر مطلب تازه نباشد بدون کامیت خارج می‌شود.
   در صورت تغییر `trends.json`، با هویت homeino-magazine-bot کامیت و پوش می‌کند.
   اجرای دستی هم با `workflow_dispatch` ممکن است. بدون Secrets، ورک‌فلو سبز
   می‌ماند و چیزی تولید نمی‌کند.

۳. دپلوی (مثلاً Vercel) از کامیت جدید، build می‌گیرد و سایت همان روز
   به‌روز می‌شود.

## اجرای دستی (لوکال)

```bash
npm run magazine:daily
# با سرویس شخصی:
LLM_BASE_URL=https://api.openai.com/v1 LLM_API_KEY=sk-... LLM_MODEL=gpt-4o-mini npm run magazine:daily
```

در سندباکس توسعه، اگر سرویس خارجی تنظیم نشده باشد، از `z-ai-web-dev-sdk`
استفاده می‌شود.

## کاور تصاویر

کاور هر بریف به ترتیب: og:image خود منبع → عکس واقعی هم‌موضوع از وب → استخر
کاور اختصاصی هومینو با چرخش بدون‌تکرار (`/public/images/trends/` و استخر محصول
`/public/images/product-pool/`). برای بریف‌های ویژه می‌توانید مسیر `cover` را
در `trends.json` دستی عوض کنید.

## ویرایش دستی

`src/content/trends/trends.json` یک فایل معمولی است؛ می‌توانید بریف اضافه/حذف
 کنید یا متن‌ها را بهبود بدهید. فقط این قواعد را نگه دارید: `slug` یکتا،
`date` به شکل `YYYY-MM-DD`، `summary` بیش از ۱۵۰ کاراکتر، و دسته از فهرست
مجاز (TREND_CATEGORY_META). تست‌ها همین‌ها را چک می‌کنند.
