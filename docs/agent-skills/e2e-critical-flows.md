# جریان‌های حیاتی E2E هومینو (اقتباس از e2e-testing در ECC v2.2.1)

اصل: فقط جریان‌هایی که پول و اعتماد می‌سازند E2E می‌گیرند — باقی با تست واحد/قراردادی پوشش می‌رود.

## ۵ جریان حیاتی (به ترتیب درآمد)

1. **ثبت‌نام و ورود** — register → login → session معتبر (`/api/auth/*`)
2. **پذیرش غرفه** — vendor register → ساخت غرفه → افزودن کالا → کالا در `products` دیده شود
3. **سبد و تسویه** — افزودن به سبد → checkout → سفارش در `account/orders` → کم شدن موجودی
4. **استودیو AI** — آپلود عکس → generate/edit → نتیجه واقعی یا کاهش صادقانه با فلگ `_degraded` (هرگز mock بی‌علامت)
5. **کشف محتوا** — مجله → پین الهام → صفحه سبک → کالای مرتبط (زنجیره سئو/تبدیل)

## قواعد اجرا (Playwright)

- اجرا روی `npx next build && npx next start` (نه dev) — رفتار تولیدی
- mock لایه پرداخت با `DevPaymentProvider` — تست واقعی پول ممنوع
- دیتابیس: شاخه تست یا seed تمیز (`scripts/seed-catalog.ts`) — هر تست داده خودش را می‌سازد و پاک می‌کند
- بدون وابستگی به API خارجی (AI/تصویر) — با fixture؛ اثبات کاهش در `/api/ai/status`
- حد نصاب: ۵ جریان بالا سبز، p95 هر جریان < 10s

## کِی می‌سازیم؟

الان نه — با لانچ پروداکشن (پس از ست‌شدن env و دامنه) اولین suite ساخته می‌شود؛
قبل از آن، تست‌های Vitest موجود (۱۶۷) + چک‌لیست دستی این فایل کفایت می‌کند.
